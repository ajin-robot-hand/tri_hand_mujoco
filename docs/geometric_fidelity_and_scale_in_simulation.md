# 로봇 시뮬레이션에서 기하학적 형상과 현실 크기 반영의 중요성 (Geometric Fidelity and Physical Scale in Simulation)

> **문서 목적**: 팀원들이 CAD 설계 부품을 MuJoCo 환경으로 옮길 때, 현실 세계의 1:1 물리 스케일과 기하학적 정밀도(회전축, 장착면 밀착, 접촉 형상)를 왜 엄격하게 일치시켜야 하는지 동역학·제어·Sim-to-Real 관점에서 체계적으로 이해하고 공통 모델링 가이드라인으로 활용하기 위함입니다.  
> **관련 프로젝트**: `tri_hand` (3지 다관절 로봇 손 시뮬레이션 및 실물 제어)

---

## 1. 개요 (Introduction)

로봇 시뮬레이션을 처음 접할 때 가장 흔히 하는 오해 중 하나는 **"시뮬레이터 화면에서 보기에 그럴듯하고 애니메이션처럼 움직이면 충분하다"** 는 생각입니다.

그러나 MuJoCo와 같은 물리 엔진은 컴퓨터 그래픽 렌더러가 아니라 **뉴턴-오일러 운동 방정식과 볼록 최적화 기반 접촉 역학을 실시간 수치 적분(Numerical Integration)하는 물리 해석기**입니다.

따라서 부품이 공중에 몇 밀리미터(mm) 떠 있거나, 부품 간 장착 위치가 어긋나 있으면 화면상으로는 사소해 보일지라도 물리 엔진 내부에서는 **완전히 다른 기구학적 레버리지와 관성 토크, 뒤바뀐 접촉 상태**를 풀게 됩니다. 이는 시뮬레이션에서 검증한 제어기를 실물 하드웨어에 배포할 때 심각한 실패(Sim-to-Real Gap)로 직결됩니다.

### "어디까지 정밀해야 하고, 어디는 단순화해도 되는가?" (현명한 타협점)

시뮬레이션에서 모든 부품을 100% 미크론 단위로 복제할 필요는 없습니다. 보통 다음과 같이 구분하여 모델링합니다:

| 구분 | 대상 요소 | 정밀도 요구 수준 | 이유 |
| :--- | :--- | :--- | :--- |
| **반드시 정밀해야 함** | **관절 회전축(Pivot) 위치 및 축 방향** | $\le 1\,\text{mm}$ 오차 | 기구학(IK/FK), 모멘트 암, 궤적의 기초 |
| **반드시 정밀해야 함** | **주요 링크 길이 및 접촉 외곽선** | $\le 1\sim2\,\text{mm}$ 오차 | 물체와의 접촉 타이밍, 파지 성공 여부 결정 |
| **반드시 정밀해야 함** | **링크별 질량 및 대략적인 무게중심(CoM)** | 실물 대비 $\pm 10\%$ 이내 | 동역학 및 모터 부하 일치 |
| **단순화 권장** | **볼트 구멍, 모따기(Chamfer), 미세 필렛** | 과감히 생략 | 충돌 계산 비용만 늘어나고 물리적 영향 없음 |
| **단순화 권장** | **충돌체 형상 (Collision Geom)** | Box / Capsule 등으로 근사 | STL 원본을 충돌체로 쓰면 관통/튕김/연산 저하 유발 |

## 2. 왜 현실 크기(Scale)가 중요한가?: 비선형 물리 스케일링 법칙

물리 엔진에서 물체의 대표 길이 스케일을 $L$이라 할 때, 크기가 변하면 이에 의존하는 물리량들은 단순 비례가 아닌 **거듭제곱(비선형)으로 급격히 변화**합니다.

| 물리량 | 스케일 의존성 | 설명 및 실무적 의미 |
| :--- | :---: | :--- |
| **길이 (Length)** | $L^1$ | 링크 길이, 변위, 회전 반경 |
| **표면적 (Area)** | $L^2$ | 공기 저항, 접촉 단면적 |
| **부피 및 질량 (Mass)** | $m \propto L^3$ | 밀도가 일정할 때 질량은 세제곱에 비례 |
| **중력 토크 (Gravity Torque)** | $\tau_g = m g L \propto L^4$ | 모터가 링크를 수평으로 유지하기 위해 버텨야 하는 정적 토크 |
| **관성 모멘트 (Inertia)** | $I \propto m L^2 \propto L^5$ | 가속·감속 시 모터에 걸리는 동적 저항 (회전 관성) |

### 실무 연결 (`tri_hand` 프로젝트)
* 본 프로젝트에서 사용하는 서보 모터는 **Dynamixel XL430-W250-T**이며, 최대 정격 토크는 **`1.4 N·m`**로 물리적 한계가 명확히 고정되어 있습니다.
* 단위 유닛의 질량 역시 실측값에 기반한 **`0.07 kg`**으로 설정되어 있습니다.
* 만약 CAD 임포트 과정에서 스케일 설정이 잘못되거나 부품 간 간격이 수 센티미터 단위로 왜곡되면, 모터가 감당해야 할 정적/동적 토크가 $L^4 \sim L^5$ 배로 왜곡되어 **시뮬레이션에서는 모터 토크가 부족해 축 처지거나(토크 포화), 반대로 너무 가볍게 휙휙 돌아가는 비현실적인 현상**이 발생합니다.

## 3. 기하학적 형상과 회전축(Pivot) 정밀도가 미치는 영향

단순히 전체 크기 비율뿐만 아니라, **부품과 부품이 만나는 조립 위치 및 관절 회전축(Pivot)의 정밀도**는 다음의 핵심 역학에 결정적 영향을 미칩니다.

### (1) 모멘트 암(Moment Arm)과 접촉력의 왜곡
* 토크와 힘의 관계는 지렛대 원리인 $\tau = r \times F$ (즉, $F = \frac{\tau}{r}$)를 따릅니다.
* 관절 회전축에서 손끝이나 물체 접촉점까지의 거리 $r$이 조립 오차(예: 7 mm)로 인해 달라지면:
  * 모터가 동일한 제어 토크 $\tau$를 발생시켜도 물체에 전달되는 **수직 항력(접촉력, Normal Force $F$)**이 수십 퍼센트 왜곡됩니다.
  * 이는 물체를 쥐었을 때 미끄러지는 마찰 한계($F_{\text{friction}} \le \mu F_N$) 조건을 완전히 바꾸어 놓습니다.

### (2) 다체 접촉(Multi-point Contact)과 접촉 모드 전환 (Contact Mode Switching)
* 3지 핸드의 목표는 3개의 손가락과 손바닥(Palm)이 물체를 감싸 쥐어 외력에 저항하는 **형상 구속(Form Closure) / 힘 구속(Force Closure)**을 달성하는 것입니다.
* 예를 들어, 손가락 힌지 베이스가 손바닥 면에서 7 mm 공중에 떠 있는 경우:
  * **시뮬레이션**: 손가락이 물체를 쥐어도 손바닥 면에 닿지 않고 손가락 끝 3점으로만 허공에서 아슬아슬하게 지탱함.
  * **실물 로봇**: 물체가 손바닥 브래킷에 단단히 밀착되어 안정적인 면 접촉 지지를 받음.
  * 결과적으로 시뮬레이션과 실물 간의 **접촉 상태(Contact Mode: 손바닥 접촉 유/무) 자체가 달라지는 치명적인 불일치**가 발생합니다.

### (3) 제어기 게인 전이 (Sim-to-Real Controller Transfer)
* MuJoCo에서 모터 액추에이터의 위치 제어 게인(`kp="12"`, `kv="0.5"`)을 튜닝할 때, 이 값들은 모델의 질량, 관성, 링크 길이에 최적화됩니다.
* 회전축 위치나 기구학적 링크 길이가 실물과 다르면, 실물 로봇에 동일한 제어 게인을 주입했을 때 **공진(Chattering), 오버슈트, 혹은 목표 각도 미달**이 발생합니다.

## 4. 팀원들이 자주 겪는 함정 (Common Pitfalls)

### 함정 1: "시각용 메쉬(Visual)와 물리 충돌체(Collision)의 착각"
* MuJoCo에서는 렌더링용 메쉬(`class="visual"`, `contype="0" conaffinity="0"`)와 물리 충돌용 도형(`class="collision"`, `contype="1" conaffinity="1"`)을 분리하여 운용합니다.
* 시각용 메쉬가 화면상에서 완벽해 보이더라도, 실제 주황색 반투명 충돌 박스(`group 3`)가 엉뚱한 위치에 있거나 떠 있으면 물리 시뮬레이션은 허공에서 반응합니다. **반드시 뷰어에서 충돌체(`3`번 키)를 켜서 물리 형상을 확인해야 합니다.**

### 함정 2: CAD 단위계(mm)와 MuJoCo 단위계(m) 불일치
* CAD 프로그램(SolidWorks, Onshape, Fusion360 등)은 기본 단위로 밀리미터(`mm`)를 사용하지만, MuJoCo는 SI 단위계인 미터(`m`)를 사용합니다.
* 메쉬 임포트 시 `scale="0.001 0.001 0.001"` 속성을 빠뜨리면 부품이 1,000배 거대해져 시뮬레이션이 즉시 발산하거나 튕깁니다.

### 함정 3: 부품을 개별 파일로 임포트하면서 발생하는 수동 조립 오차
* 어셈블리(Assembly) 상태의 전체 CAD 좌표계를 공유하지 않고 부품을 개별 STL로 내보낸 뒤, XML 파일에서 눈대중(`pos="x y z"`)으로 위치를 맞추면 이번 사례처럼 **7.1 mm가 공중에 뜨는 기구학적 오차**가 누적됩니다.
* 가능하면 CAD 어셈블리 상에서 각 부품의 상대 원점 좌표를 정밀 측정하여 XML에 입력해야 합니다.

## 5. 모델링 및 검증 체크리스트 (Actionable Checklist)

새로운 부품을 모델링하거나 기존 모델을 검증할 때 다음 체크리스트를 순서대로 확인하세요:

- [ ] **단위계 확인**: 모든 거리 단위가 `m`, 질량 단위가 `kg`, 각도가 `radian`으로 정의되었는가?
- [ ] **장착면 밀착 확인**: 지지대(Palm)와 구동부(Hinge frame) 사이에 의도치 않은 공중 틈(`Gap`)이 없는가?
- [ ] **관절 회전축(Pivot) 정렬**: XML의 `<joint pos="..." axis="...">`가 CAD 어셈블리의 실제 회전 핀 중심축과 정확히 일치하는가?
- [ ] **충돌체 프리미티브 근사**: 복잡한 STL 메쉬를 충돌체로 직접 쓰지 않고, 박스(`box`)나 캡슐(`capsule`) 등으로 적절히 근사했는가?
- [ ] **초기 관통(Penetration) 여부**: $t=0$ 시점에서 링크 충돌체끼리 겹쳐있지 않은가? (초기 겹침 시 시뮬레이션 폭발 원인)
- [ ] **하드웨어 스펙 동기화**: 모터의 토크 한계(`forcerange`) 및 질량이 실제 사용하는 부품(XL430) 스펙과 일치하는가?
- [ ] **뷰어 시각화 교차 검증**: MuJoCo 뷰어에서 지오메트리 그룹 토글(`1`: Visual 메쉬, `3`: Collision 충돌체)을 통해 두 형상이 어긋남 없이 일치하는지 육안으로 확인했는가?
