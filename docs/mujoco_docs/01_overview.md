# MuJoCo 개요 및 핵심 개념 (MuJoCo Overview)

> 원문 출처: [MuJoCo Documentation - Overview](https://mujoco.readthedocs.io/en/stable/overview.html)  
> 본 문서는 MuJoCo의 공식 개요 문서에서 **초보자가 시뮬레이션을 이해하고 모델링할 때 반드시 알아야 하는 핵심 원리와 주의사항**을 정리한 문서입니다. (코드 예제는 실습 튜토리얼에서 별도로 다룹니다.)

---

## 1. MuJoCo란?

- **MuJoCo (Multi-Joint dynamics with Contact)**: 관절 구조를 가진 다체(articulated body)가 주변 환경과 접촉(Contact)하며 상호작용하는 물리 현상을 빠르고 정확하게 시뮬레이션하기 위한 물리 엔진입니다.
- **주요 활용 분야**: 로보틱스, 생체역학(Biomechanics), 강화학습 및 머신러닝, 그래픽스 애니메이션 등.
- 2021년 10월 Google DeepMind에 인수되었고, 이후 2022년 5월 오픈소스로 완전 무료 공개되었습니다.

---

## 2. 엔진의 핵심 철학 및 특징

### (1) 일반화 좌표계 (Generalized / Joint Coordinates)
- **로보틱스 표준 방식**: 물체들의 위치를 월드 데카르트 좌표(X, Y, Z)가 아니라 부모-자식 관절 간의 상대 각도/변위(Joint Coordinates)로 기술합니다.
- **특징**:
  - 조인트 제한 및 기구학적 구속이 수식 표현 자체에 내재되어 있어 수치적 불안정성(관절 분리 현상 등)이 원천적으로 발생하지 않습니다.
  - 관절이 복잡하게 얽힌 로봇 팔, 다관절 손, 보행 로봇 시뮬레이션에 가장 적합합니다.

### (2) 볼록 최적화 기반 접촉 역학 (Convex Optimization Contact)
- 일반적인 게임 물리 엔진은 접촉 마찰을 풀 때 선형 상보성 문제(LCP, NP-hard)를 풀어 근사치를 내거나 튕김/오류가 잦습니다.
- MuJoCo는 접촉 물리를 **볼록 최적화(Convex Optimization) 문제**로 공식화하여 빠르고 매끄러우며, 역역학(Inverse Dynamics) 계산이 유일하게 성립하도록 설계되었습니다.

### (3) 데이터 지향 설계 (Data-Oriented Architecture: mjModel과 mjData의 분리)
MuJoCo는 객체 지향이 아닌 데이터 지향 구조로 설계되어 전역 변수를 쓰지 않고 메모리 할당을 실행 중 발생시키지 않습니다.

- **`mjModel` (정적 모델 구조체)**:
  - 모델의 고유하고 불변하는 물리적 명세(링크 길이, 질량, 관성, 관절 한계, 형상 정보 등)를 담고 있습니다.
  - 한 번 로드되면 런타임 동안 변경되지 않습니다.
- **`mjData` (동적 상태 및 연산 버퍼 구조체)**:
  - 시뮬레이션 진행에 따라 계속 변하는 동적 변수(`qpos`: 위치, `qvel`: 속도, `qacc`: 가속도, `sensordata`: 센서값, 접촉력 등)와 중간 연산 임시 버퍼를 담습니다.
  - 런타임 중 추가 메모리 할당(malloc) 없이 초기화 시 잡힌 버퍼를 재사용합니다.
- **장점**: 하나의 동일한 `mjModel`을 공유하면서 여러 개의 `mjData`를 복제하면, 멀티스레딩이나 대규모 병렬 강화학습 시뮬레이션을 매우 가볍고 안전하게 수행할 수 있습니다.

## 3. 모델 라이프사이클 및 구성 파일

| 레벨 | 파일 형식 | 메모리 구조체 | 설명 |
| :--- | :--- | :--- | :--- |
| **High Level** | `MJCF (.xml)`, `URDF` (파일) | `mjSpec` (메모리 C 구조체) | 사람이 읽고 편집할 수 있는 원본 모델 표현 |
| **Low Level** | `MJB (.mjb)` (바이너리 파일) | `mjModel` (메모리 C 구조체) | 파서/컴파일러를 거쳐 연산 최적화가 완료된 구조체 |

- **MJCF (MuJoCo XML Format)**: MuJoCo 고유의 XML 모델링 언어로, CSS처럼 기본값(default class) 상속 구조를 지원하여 코드가 매우 간결합니다.
- **`mjSpec`**: MJCF/URDF를 파싱한 직후, 컴파일 전 단계의 모델을 담는 메모리상 C 구조체입니다. XML 텍스트 자체가 아니라 High Level 표현의 메모리 버전이라는 점에 유의하세요.
- **워크플로우**: 텍스트 에디터로 MJCF 작성 $\rightarrow$ MuJoCo 컴파일러가 유효성 검사 및 질량/기구학 자동 계산 $\rightarrow$ 메모리에 최적화된 `mjModel` 생성 $\rightarrow$ `mjData`를 생성하여 물리 연산 루프 수행.

## 4. 기구학 트리 구성 요소 (Kinematic Tree Elements)

MuJoCo의 물리 세계는 부모-자식 트리 구조로 묶입니다. 최상위 루트는 항상 정적 월드인 **`worldbody`**입니다.

### (1) Body vs Geom vs Site (가장 중요한 구분!)
초보자가 가장 혼동하기 쉬운 3가지 핵심 요소의 차이입니다:

1. **`Body` (강체 뼈대)**:
   - 기구학 트리의 노드를 형성합니다.
   - 질량(Mass)과 관성 모멘트(Inertia), 그리고 고유 기준 좌표계를 가집니다.
   - **자체적인 시각적 모양이나 충돌 영역은 없습니다.** (순수한 물리적 뼈대 역할)
2. **`Geom` (기하 형상 - 시각 및 충돌체)**:
   - Body에 단단히 부착되는 3D 형상(구, 캡슐, 상자, 실린더, 메쉬 등)입니다.
   - **시각적 렌더링**과 **물리적 충돌(Collision) 감지**를 전담합니다.
   - Geom의 부피와 밀도를 바탕으로 부모 Body의 질량과 관성 모멘트를 자동 계산해 주기도 합니다.
   - *주의: 비볼록(Concave) 메쉬는 MuJoCo 충돌 감지기가 Convex Hull(외곽 볼록 껍질)로 단순화하므로, 복잡한 비볼록 물체는 여러 개의 단순 볼록 Geom을 하나의 Body에 묶어 구성해야 합니다.*
3. **`Site` (무질량 기준점/마커)**:
   - Body 좌표계 내의 특정 위치/방향을 지정하는 가벼운 마커입니다.
   - **질량이 없고, 충돌하지 않습니다.**
   - 센서(IMU, 터치 센서) 위치, 와이어/힘줄(Tendon)의 통과점 및 끝단, 힘 적용점 등을 정의할 때 사용합니다.

### (2) Joint (관절)와 DOF (자유도)
- **자유도 추가 원리**: 일반 게임 엔진은 자유롭게 떠 있는 물체 사이를 조인트로 묶어 자유도를 **제거(Remove)**하지만, MuJoCo는 조인트가 없으면 부모에게 완전히 **용접(Weld)**되며, Joint 태그를 넣어야만 해당 축의 자유도가 **추가(Add)**됩니다.
- **관절의 4가지 유형**:
  - `hinge`: 1축 회전 관절 (가장 흔함, 로봇 관절)
  - `slide`: 1축 병진/직동 관절 (슬라이더, 피스톤)
  - `ball`: 3축 구면 회전 (볼 조인트, 회전은 쿼터니언으로 표현)
  - `free`: 6자유도 부유 관절 (공중에 자유롭게 떠 있는 물체에 부여)
- **Joint(위치) vs DOF(속도/힘)**:
  - Joint는 위치 차원(`qpos`)에 대응합니다 (예: Ball 관절 위치는 4차원 쿼터니언).
  - DOF는 속도/힘 차원(`qvel`, `qacc`)에 대응합니다 (예: Ball 관절 속도는 3차원 각속도 벡터).
  - 전체 시스템의 위치 차원 크기는 `mjModel.nq`, 속도/자유도 차원 크기는 `mjModel.nv`입니다.

## 5. 독립 구성 요소 (Stand-alone Elements)

특정 단일 Body에만 귀속되지 않는 글로벌/상호작용 요소들입니다.

- **`Tendon` (힘줄/와이어)**:
  - 여러 Site나 Geom을 경유하는 최단 경로 와이어를 모델링합니다. (손가락 와이어 구동, 풀리 메커니즘, 관절 간 기계적 연동 등에 사용)
- **`Actuator` (구동기/모터)**:
  - 제어 입력(토크, 위치 지령 등)을 받아 시스템에 힘을 가합니다.
  - 전송 방식(Joint, Tendon, Site 등), 활성화 동역학(Activation dynamics), 힘 생성 수식이 모듈형으로 결합됩니다.
- **`Sensor` (센서)**:
  - 관절 각도/속도, 가속도계, 자이로스코프(IMU), 힘/토크(F/T), 터치 압력 등을 시뮬레이션하여 `mjData.sensordata` 배열에 기록합니다.
- **`Equality` (구속 조건)**:
  - 기구학 트리 구조 외에 추가적인 폐루프(Loop joint) 구속, 두 바디 간의 용접, 두 관절 간의 비례 결합 등을 강제합니다.

## 6. 초보자가 반드시 겪는 함정과 주의사항 (Clarifications)

공식 문서의 "Clarifications" 섹션에서 다루는, 다른 엔진 사용자나 초보자가 가장 많이 실수하는 핵심 내용입니다.

### (1) 발산 현상 (Divergence)
- 시뮬레이션 도중 물체가 갑자기 화면 밖으로 날아가거나 NaN이 뜨는 현상입니다.
- 공식 문서(Overview)는 "발산은 물리 시뮬레이션 전반에 흔히 발생하는 현상이며, 반드시 모델이나 시뮬레이터의 버그를 뜻하지는 않는다. 오히려 선택한 적분기(integrator)에 비해 타임스텝이 너무 크다는 신호"라고 설명합니다.
- **주요 원인**:
  1. 물리 연산 타임스텝(`timestep`)이 사용 중인 적분기, 액추에이터 게인(Kp), 관절 댐핑에 비해 너무 큼.
  2. 모델 초기 상태(`t=0`)에서 물체 간 지오메트리가 서로 겹쳐(Penetration) 폭발적인 반발력이 발생함. (이 항목은 Overview의 Clarifications 섹션이 아닌 모델링 가이드 쪽 내용이지만, 실무적으로 매우 흔한 원인이라 함께 정리)
- **대응책**: 타임스텝을 줄이거나 더 안정적인 적분기로 전환하고, 초기 자세의 충돌 간섭을 해소해야 합니다.
- 참고: `mjWARN_BADQACC`는 이 발산 상황에서 실제로 발생하는 MuJoCo API 경고 상수이지만, Overview 문서 자체에 언급된 용어는 아니며 API 레퍼런스에 정의되어 있습니다.

### (2) 물리 단위계(Units)와 각도(Angle)의 함정
- MuJoCo는 기본적으로 단위계가 명시되어 있지 않으나, 기본 상수들이 **MKS 단위계 (m, kg, s, N, N·m)**를 기준으로 설계되어 있습니다:
  - 기본 중력: `-9.81` ($m/s^2$)
  - 기본 밀도: `1000` ($kg/m^3$, 물의 밀도)
- **각도 규칙**:
  - MJCF XML 상에서는 `<compiler angle="degree"/>` 설정을 통해 각도를 도(Degree) 단위로 편리하게 기입할 수 있습니다.
  - 하지만 **엔진 내부(`mjModel`, `mjData`)의 모든 수치 계산과 C/Python API 값은 항상 라디안(Radian)**으로 처리됩니다. (예: 각속도는 rad/s, 스프링 상수는 Nm/rad)

### (3) 부모-자식 충돌 예외 규칙 (Surprising Collisions)
- MuJoCo는 기본적으로 **직접적인 부모-자식 관계에 있는 Body 간에는 충돌(Geom contact)을 무시**합니다 (관절 부위의 불필요한 마찰/간섭 방지).
- **예외**: 부모가 **`worldbody`이거나 자유도가 없는 정적(Static) Body인 경우**에는 자식과의 충돌이 정상 활성화됩니다 (바닥이나 벽을 뚫고 지나가는 것을 방지하기 위함).
- **흔한 실수**: 공중에 띄워둔 로봇 베이스의 `free` 관절을 주석 처리하면, 베이스가 정적 물체가 되면서 이전에 무시되던 링크 간 충돌이 갑자기 활성화되어 로봇이 요동치거나 튕겨 나갈 수 있습니다. (이 경우 `mocap="true"` 바디를 쓰거나 충돌 필터링(`contype`, `conaffinity`, `exclude`)을 명시해야 함)

### (4) 접촉 미끄러짐과 소프트 제약 (Softness & Slip)
- MuJoCo의 접촉 모델은 수학적으로 완전히 딱딱한(Rigid) 강체가 아닌 부드러운 구속(Soft constraint) 모델입니다.
- 경사면이나 마찰이 있는 바닥에서 물체가 아주 미세하게 서서히 미끄러지는(Creep/Slip) 현상이 발생할 수 있습니다.
- 이는 마찰력이 부족해서가 아니라 접촉 수식의 부드러움 때문이며("힘을 더 세게 줄수록 항상 더 큰 가속도가 나온다"는 소프트 제약의 본질적 특성), 단순 마찰 계수를 올려서는 해결되지 않습니다.
- **대응책**: 구속 임피던스 파라미터(`solref`, `solimp`)를 조절하거나, `NoSlip` post-processor를 사용해야 합니다. 단, `NoSlip`을 사용하면 더 이상 순수한 볼록 최적화 문제를 푸는 것이 아니게 된다는 점(정확도 트레이드오프)에 유의해야 합니다.

### (5) 자유 부유 물체 (Free Joint)의 데이터 표현
- 일반적인 바디는 부모에 종속되므로 월드 좌표를 직접 임의 지정할 수 없지만, `free` 조인트를 가진 물체는 직접 제어가 가능합니다.
- `mjData.qpos` (위치): **7개 값** (3D 위치 [x, y, z] + 3D 자세 회전 단위 쿼터니언 [w, x, y, z], 월드 좌표계)
- `mjData.qvel` (속도): **6개 값** (3D 선속도 [월드 좌표계] + 3D 각속도 [로컬 바디 좌표계])
- 각속도가 쿼터니언 접공간(Tangent space) 특성상 로컬 좌표계로 표현된다는 점에 유의해야 합니다.

## 7. 권장 모델링 체크리스트

1. **단위 검증**: CAD 모델 임포트 시 mm 단위 메쉬는 `scale="0.001 0.001 0.001"`로 미터 단위 변환 필수.
2. **충돌체 분리**: 시각용 메쉬(`mesh`, 복잡한 외형)와 물리 충돌용 도형(`box`, `capsule`, 단순 볼록체)을 철저히 분리.
3. **초기 관통 제거**: 시뮬레이션 시작(`t=0`) 순간 링크끼리 또는 환경과 겹쳐있지 않은지 뷰어의 Contact 표시로 확인.
4. **단계적 검증**: 수동 조작 및 외력 테스트 $\rightarrow$ 중력 및 수동 관절 감쇠 확인 $\rightarrow$ 액추에이터 제어기 결합 순으로 점진적 진행.
