# MuJoCo 학습 문서 작성 가이드 (재사용 프롬프트)

> 이 문서는 `docs/` 폴더에 MuJoCo 공식 문서(https://mujoco.readthedocs.io) 내용을 정리할 때
> 매번 동일한 품질과 톤을 유지하기 위한 **작성 지침 겸 재사용 프롬프트**입니다.
> 다음 문서를 요청할 때 "docs/00_writing_guide.md 지침대로 정리해줘" 형태로 함께 전달하세요.

---

## 1. 대상 독자

- **MuJoCo를 처음 접하는 사람**을 기준으로 작성합니다. 전문 용어가 처음 나올 때는 반드시 쉬운 설명이나 비유를 덧붙입니다.
- 단, 이 문서는 `tri_hand`(3지 로봇 손) 프로젝트에서 실제로 쓸 내용이므로, 가능하면 이 프로젝트의 실제 상황(`AGENTS.md`의 좌표계·하드웨어 규칙 등)과 연결해 예시를 듭니다.
  - 예: "회전 관절(hinge joint)" 설명 시 → "본 프로젝트의 손가락 관절이 바로 이 타입이며, 축은 `+X`, 오므림 부호는 손가락 위치에 따라 다릅니다."

## 2. 원문 검증이 최우선 (가장 중요한 규칙)

1. 문서를 작성하기 전, 반드시 해당 mujoco.readthedocs.io 원문 페이지를 **직접 fetch해서 원문을 확인**합니다. 기억이나 추측으로 작성하지 않습니다.
2. 정리한 모든 핵심 주장(수치, 기본값, 용어, 예외 규칙 등)은 원문과 대조해 **사실 검증(fact-check)**을 거칩니다.
3. 원문에 명시된 내용과, 이해를 돕기 위해 덧붙인 **부가 설명/다른 출처 정보**는 반드시 구분해서 표기합니다.
   - 예: "공식 문서는 다음과 같이 설명합니다: '...'" (원문 인용) vs. "(참고: 이 부분은 Overview 문서가 아닌 API 레퍼런스 내용입니다)" (부가 정보 표시)
4. 날짜, 버전, 상수명, 파라미터명처럼 **틀리기 쉬운 구체적 사실**은 특히 주의해서 원문 표현 그대로 확인합니다.
5. 문서 작성이 끝나면 스스로 원문과 한 번 더 대조하는 검증 패스를 거친 뒤 결과를 보고합니다 (이전 대화에서 했던 것과 동일한 방식).

## 3. 문서 구조 일관성

`01_overview.md`에서 확립된 구조를 기본 템플릿으로 따릅니다:

```markdown
# [주제] (영문 원어 병기)

> 원문 출처: [페이지 제목](URL)
> 본 문서는 ... 를 정리한 문서입니다. (범위와 목적 한 줄 요약)

---

## 1. [핵심 개념 A]
- 정의, 왜 중요한지, 처음 접하는 사람이 헷갈리는 지점 위주로 서술

## 2. [핵심 개념 B]
...

## N. 초보자가 반드시 겪는 함정과 주의사항 (Clarifications)
- 원문의 "Clarifications"/"Common pitfalls" 류 섹션이 있다면 반드시 별도 절로 강조

## N+1. 권장 체크리스트
- 실습/모델링 시 바로 적용 가능한 액션 아이템 목록으로 마무리
```

- 섹션 번호(`## 1.`, `## 2.` ...)와 구분선(`---`)을 일관되게 사용합니다.
- 개념 비교가 필요할 때는 표(table)를 적극 활용합니다.
- 굵은 글씨(`**핵심 용어**`)로 핵심 키워드를 강조하되 과용하지 않습니다.
- 코드/실습 예제는 이 개념 문서에 넣지 않고 `tutorial/` 쪽 실습 문서에서 별도로 다룹니다 (관심사 분리).

## 4. 논리적 서술 원칙

- **정의 → 이유(왜 이렇게 설계되었는가) → 실무 영향** 순서로 서술합니다. 단순 사실 나열을 지양합니다.
- 다른 엔진(게임 물리 엔진 등)과 대비해서 설명하면 이해가 쉬운 개념은 대비를 활용합니다 (원문이 그런 대비를 사용하는 경우 특히).
- 용어는 최초 등장 시 "한글 표현 (영문 원어)"로 병기하고, 이후에는 한글 표현으로 통일해서 사용합니다.
- 문장은 간결하게, 한 문단에 한 가지 주장만 담습니다.

## 5. 검토 시 자체 체크리스트

문서를 완성한 뒤 다음을 스스로 점검합니다:

- [ ] 원문을 실제로 fetch해서 대조했는가?
- [ ] 수치/날짜/상수명 등 구체적 사실이 원문과 일치하는가?
- [ ] 원문에 없는 보충 설명은 명확히 구분 표시했는가?
- [ ] MuJoCo 초보자가 이해할 수 있는 수준으로 용어를 풀어썼는가?
- [ ] 가능한 경우 `tri_hand` 프로젝트의 실제 좌표계/하드웨어 규칙과 연결했는가?
- [ ] 문서 구조(섹션 번호, 표, 체크리스트 마무리)가 기존 문서들과 일관되는가?
- [ ] 파일명이 `NN_주제.md` 형식(2자리 번호 + 주제)으로 이전 문서와 순서가 맞는가?

## 6. 파일 명명 규칙

- `docs/NN_주제.md` 형식 (예: `01_overview.md`, `02_mjcf_modeling.md`, `03_contact_and_collision.md`)
- 번호는 학습 진행 순서를 따르며, 기존 문서 번호를 건너뛰거나 재사용하지 않습니다.
